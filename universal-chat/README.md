# Universal Chat
 
一個**純前端、零建置、單資料夾可執行**的多模型聊天介面。
支援 **OpenRouter** 與 **Poe** 兩種供應商，所有資料（對話、設定、API Key）預設只存在你自己的瀏覽器中。
v2.4 起改用 **IndexedDB** 儲存，**不再受限於舊版 localStorage 約 5 MB 的上限**；
並延續 v2.3 的**暫時對話**、**多對話同時生成**、**資料夾排序**與**可調寬度側邊欄**。

## 快速開始

### 1. 取得 API Key（擇一即可）
 
**OpenRouter**
 
1. 前往 <https://openrouter.ai> 註冊並登入。
2. 到 **Keys** 頁面建立一組 API Key（格式類似 sk-or-v1-…）。
3. OpenRouter 提供多個 `:free` 結尾的免費模型，不儲值也能先試用。
 
**Poe**
 
1. 前往 <https://poe.com> 登入。
2. 到 **Settings → API Key** 取得金鑰。
3. Poe 沒有公開的模型目錄 API，模型清單由你在本 App 內自行維護。

### 2. 開啟應用程式
 
**方式 A — 直接開啟（最簡單）**
 
    下載整個資料夾 → 用瀏覽器開啟 index.html
 
本專案刻意不使用 ES Module，因此用 file:// 直接開啟也能完整運作。
 
**方式 B — 本機伺服器（建議）**
 
    python -m http.server 8080     # Python
    npx serve .                    # Node
 
然後開啟 <http://localhost:8080>。
 
**方式 C — 靜態託管**
 
丟到 GitHub Pages / Cloudflare Pages / Netlify / Vercel 即可，無需建置步驟。

### 3. 設定並開始聊天
 
1. 首次開啟會自動跳出設定視窗 → **API** 分頁。
2. 選擇**服務供應商**（OpenRouter 或 Poe）→ 貼上對應的 API Key → 按「驗證」。
3. 到 **模型與參數** 分頁按「選擇…」挑一個模型。
4. 回主畫面輸入訊息，按 <kbd>Enter</kbd> 送出。

### ⚙️ 生成參數
 
Temperature、Top P、Top K、Max Tokens、Frequency / Presence / Repetition Penalty、Seed、Stop Sequences、Reasoning Effort。
支援 **「本對話專用參數」**：全域設定一份、特定對話另一份。

### 🧩 上下文控制
 
- 全域系統提示詞 ＋ 每則對話獨立系統提示詞。
- **歷史訊息上限**：只送最近 N 則，控制成本。
- **自動摘要**：訊息過多時自動請模型摘要舊訊息——而且**完全透明可管**：
  頂列常駐「📝 已摘要 N 則」、🎛️ 本對話設定內可直接檢視／編輯／清除摘要文字，
  也可用 `/summary` 隨時查閱（詳見 [自動摘要](#自動摘要) 一節）。
- **自動命名**：第一次回覆後自動產生對話標題。
- 上下文用量儀表：頂列顯示「約 x / y tokens」，超過警示比例會出現 ⚠️。

### ✍️ 訊息互動
 
- 串流逐字輸出，可隨時 <kbd>Esc</kbd> 停止。
- **⬆ 回頂按鈕**：滑鼠移到任一則訊息上，右上角會出現懸浮按鈕，一鍵平滑跳回該則訊息的開頭——很長的回覆捲到中段也能立刻回去。
- 每則訊息可：**複製、編輯、重新生成、刪除、建立分支、朗讀、加入書籤**。
- **↻ 重試**：失敗的回覆在操作列直接「重試」——沿用原模型與上下文重送，成功後**原地替換**，不用編輯再重生。
- **✏️ 助理訊息也可編輯**：修正幻覺、修剪廢話後僅儲存，不會觸發重新生成（使用者訊息仍是「儲存並重新送出」）。
- **⏩ 繼續生成**：回覆被 max_tokens 截斷時，訊息尾端出現「繼續生成」按鈕，從中斷處接著寫、append 回同一則，可連續多次；token 用量與耗時逐段累計。
- **🔖 書籤與對話內導航**：任一則訊息可加入書籤；對話頂部出現書籤列，點擊直接跳轉，<kbd>Alt</kbd>+<kbd>[</kbd> / <kbd>]</kbd> 在書籤間循環切換——回頂解決「回到這則的開頭」，書籤解決「在幾百則裡找到那則」。
- **📎 附件可下載**：歷史訊息中的文字附件有 ⤓ 下載鈕（原始檔名與 MIME）；圖片點擊可開新視窗檢視。
- 編輯／刪除訊息後**保留目前的捲動位置**，不會被拉回對話底部。
- 🌿 **分支**：從任一則訊息開一個新對話，保留前面的脈絡。
- 💭 **思考過程**：支援 reasoning 的模型會顯示可折疊的思考內容。
- 每則訊息顯示**完整日期＋時間**（例如 `2025/01/08 14:03`），滑過可看到秒數。
- 助理回覆會顯示 **⏱ 生成耗時**（生成中即時跳動，例如 `⏱ 1 分 32 秒`）；耗時也會寫進 JSON / Markdown / CSV 匯出。

### ✨ AI 自動命名
 
- 兩個入口都有 **「✨ AI 產生」** 按鈕：
  - 側邊欄 → 對話 ✏️ → **重新命名對話**
  - 頂列 🎛️ → **本對話設定** → 標題欄位旁
- 讀取對話前 4 則 + 後 2 則內容，產生 16 字內的標題，**先填進輸入框讓你確認／修改**。
- 自動清洗 reasoning 模型輸出的思考標籤、引號、句尾標點。
- 手動命名過的對話會被標記 titleLocked，自動命名不會再覆蓋它。
- 也可用 `/autotitle` 指令，或在設定指定專用的「標題產生模型」。

### ∑ 數學公式
 
- 支援 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`、`\begin{aligned}…\end{aligned}`。
- 渲染前先把數學從 Markdown 抽離，因此底線、星號、上標符號不會被吃掉。
- 兩段式引擎：**KaTeX**（需要時才載入、可自架）＋ **內建輕量渲染器**（零依賴 fallback）。
- 串流友善、公式結果有快取；複製時自動還原成 LaTeX 原始碼。

### 🎨 介面
 
- 5 種主題：深色、淺色、午夜藍、紙墨、跟隨系統；8 色強調色 + 自訂色。
- 字級、內容寬度、訊息密度可調；14 個顯示開關。
- Markdown：標題、清單、任務清單、表格、引言、連結、圖片、行內程式碼（含雙反引號 `` ``code`` ``）。
- 程式碼區塊：語法高亮、語言標籤、一鍵複製、下載成檔案、切換自動換行、行號。
- **圍欄遵循 CommonMark 規則（逐行解析）**：程式碼內容中的 ``` （字串字面值、docstring、巢狀範例）不會再誤斷區塊；支援長圍欄（4 個反引號）包短圍欄，以及波浪線 `~~~` 圍欄。
- **專注模式**：<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> 一鍵隱藏側邊欄與頂列，只留訊息與輸入區；再按一次或 <kbd>Esc</kbd> 退出。
- 響應式：手機為抽屜式側邊欄；支援列印。
- 側邊欄寬度可拖曳調整（200–520 px，雙擊右緣還原預設 272 px），會記在設定中；把手也可用鍵盤操作。
- 資料夾可排序：滑過資料夾標頭出現 ↑ ↓，或直接拖曳標頭到目標位置；順序會隨 `_folders.json` 一起同步。

### 📎 檔案與 📷 圖片
 
- 拖放整個視窗、點 📎 選檔、或直接 <kbd>Ctrl</kbd>+<kbd>V</kbd> 貼上圖片。
- 文字／程式碼檔會被讀成內容並以程式碼區塊附在提示詞中（含檔名）。
- 圖片以 Vision（image_url）格式送出，模型不支援時自動附註而不會失敗。
- 附件列可收合：附加多個檔案時自動收成一行摘要（📎 N 個附件 · 總大小），展開後超出高度可捲動，**不會推擠聊天區**，也**沒有數量上限**。

### 🎧 語音
 
- 語音輸入（Web Speech API）：中文（台灣／普通話）、英日韓，可「說完自動送出」。
- 朗讀回覆（TTS）：可選語音、語速、音高，支援自動朗讀新回覆；朗讀時會略過程式碼與數學式。

### 📚 提示詞庫
 
- 9 組內建人格（通用助理、程式導師、程式碼審查、中文編輯、翻譯、循序教學、資料分析、數學家教、蘇格拉底式）。
- 可新增／編輯／刪除自訂提示詞，一鍵「設為系統提示詞」或「插入輸入框」。

### 💾 資料
 
- IndexedDB 儲存：容量由瀏覽器配額決定（通常數 GB），大量圖片附件也不會爆掉。
- 首次啟動自動從舊版 localStorage 遷移，完成後釋放舊空間，**不需要任何手動操作**。
- 單一對話匯出：**下拉選單選格式** — JSON / Markdown / 純文字 / 獨立 HTML / CSV。
- 整體備份匯出／匯入（匯入時可選「合併（三方合併，不遺失）」或「覆蓋」）。
- 儲存空間統計（顯示 App 資料量與瀏覽器配額）、刪除所有封存對話、清除全部資料。
- **多分頁一致**：同一瀏覽器的多個分頁透過 BroadcastChannel 互通變更，內容沒變就不重繪。

### ☁️ GitHub 同步（選用）
 
- 一個對話 = repo 內一個 JSON 檔，跨裝置看到同一份歷史。
- **不會覆蓋資料**：寫入帶 sha 樂觀鎖，衝突時自動「重抓 → 三方合併 → 重推」。
- 訊息以 id 聯集合併；對話 / 訊息 / 資料夾 / 提示詞的刪除都採墓碑，**不會遺失也不會復活**。
- **背景同步不會讓畫面閃爍**：只有本機資料真的被改動、且內容指紋不同時才重繪。
- 可把舊對話卸載到雲端，只在本機留標題，**大幅節省瀏覽器儲存空間**。
- **大檔友善**：超過約 900 KB 的對話自動改走 Git Data API；目錄列表走 git trees API，不受 1000 檔截斷。
- 完全可選：不啟用時零網路請求、零行為改變。

## 暫時對話
 
適合「只想問一下、不想留紀錄」的情境（查資料、貼敏感內容、測試提示詞）。

### 怎麼開
 
| 方式 | 操作 |
| --- | --- |
| 按鈕 | 側邊欄上方的 **🕶️** |
| 快捷鍵 | <kbd>Alt</kbd>+<kbd>T</kbd> |
| 指令 | `/temporary` |

### 行為
 
| 項目 | 暫時對話 | 一般對話 |
| --- | --- | --- |
| 寫入 IndexedDB | ❌ 完全不寫 | ✅ |
| 同步到 GitHub | ❌ 不推送、不建立檔案 | ✅（若啟用） |
| 出現在整體備份 | ❌ | ✅ |
| 重新載入頁面後 | **消失** | 保留 |
| 側邊欄外觀 | 🕶️ 圖示＋橘色虛線邊 | 💬 / 📌 |
| 其他功能（模型、附件、匯出、分支…） | 全部照常可用 | — |
 
> 關閉分頁前若還有內容未消化的暫時對話，瀏覽器會出現「確定要離開嗎」提示。
> 想留下紀錄，可以先用 📤 匯出，或直接轉為永久對話。

### 改變心意：互相轉換
 
| 方向 | 操作 | 說明 |
| --- | --- | --- |
| 暫時 → 永久 | 側邊欄該對話的 **💾** 按鈕，或指令 `/keep` | 保留同一個對話，立刻開始儲存並在下次同步時上傳 |
| 永久 → 暫時 | 側邊欄該對話的 **🕶️** 按鈕 | 需確認。會把內容搬進一個新的暫時對話，**並刪除本機（與雲端）的舊副本** |
 
> ⚠️「永久 → 暫時」等同刪除已儲存的版本，執行前請確認是否需要先匯出。

## 多對話同時生成
 
v2.3 起，生成回覆的工作是**綁在對話上，而不是綁在畫面上**：
 
- 模型還在輸出時，你可以直接點側邊欄切到別的對話、甚至同時對另一個對話送出新問題。
- 離開的那個對話**不會被中斷**；文字持續累積到資料中，切回去就會看到完整（或仍在增長的）內容。
- 側邊欄對該對話顯示 **⏳ 轉圈圖示**與淡色底，滑過提示「正在生成回覆…」。
- 頂列狀態、輸入框下方的進度文字、以及「⏹ 停止」按鈕**只反映目前這個對話**。
- <kbd>Esc</kbd>／⏹ 只停止**目前這個**對話的生成，不會影響其他背景工作。
- 有任何對話正在生成時，GitHub 自動同步會自動延後，畫面不會被打斷。

## 自動摘要
 
「自動摘要舊訊息以節省 tokens」不再是黑盒子：摘要的內容、進度與觸發時機全部可見、可改。

### 它在做什麼
 
當對話訊息數達到門檻（預設 30，可在「設定 → 上下文」調整），會自動請模型把較舊的訊息
壓縮成一段條列式摘要，存進該對話，並記住已壓縮到第幾則。之後每次送出請求，摘要都會以
「【先前對話摘要】」系統訊息插在歷史訊息之前，**最後 8 則永遠保留原文**。

### 四個低調的入口
 
| 入口 | 形式 | 用途 |
| --- | --- | --- |
| 頂列 | 一行小字「📝 已摘要 N 則」（只有自訂摘要時顯示「📝 含自訂摘要」） | 被動監看狀態 |
| 🎛️ 本對話設定 | 折疊的「📝 自動摘要」區塊（從未產生過摘要時整塊隱藏） | 檢視／直接編輯摘要文字，按「儲存」生效 |
| 摘要完成的當下 | Toast 提示；開啟「開發者模式」時另附一張列出本次摘要全文的暫時性系統卡 | 即時知道發生了什麼 |
| 指令 | `/summary` | 隨時查閱目前摘要與壓縮進度 |

### 三個維護按鈕（🎛️ 內）
 
| 按鈕 | 行為 |
| --- | --- |
| 🔄 立即重新摘要 | 忽略門檻，立刻把尚未壓縮的舊訊息再摘要一次、接在現有文字後面 |
| ↺ 只重設進度 | 把「已壓縮到第幾則」歸零但保留文字；下次達門檻時同一批舊訊息會再被摘要一次 |
| 🗑️ 清除摘要 | 清空文字並重設進度，之後從頭重新累積 |
 
> 💡 摘要只是普通欄位——直接編輯文字後按「儲存」即可生效，你寫什麼模型就收到什麼；
> 也可以自行增補重點，下一輪摘要會沿用既有文字作為基礎。
> 若把文字清空，連「已跳過前 N 則」的紀錄也會一起放棄（避免那些訊息既不在摘要裡、又不再被送出）。
 
> 🔍 想看「最終送出去的完整 payload」（含摘要如何被組装）：開啟「設定 → 介面 → 開發者模式」，
> 每次請求前都會以系統卡印出完整的 messages 陣列。

## 數學公式
 
若模型回覆出現「方差縮小為 $\sigma^2/n$」這種原始 LaTeX，代表渲染被關閉或引擎載入失敗：
 
1. 設定 → 介面 → **渲染 LaTeX 數學公式** 是否開啟。
2. 引擎選「自動」時會從 CDN 載入 KaTeX；離線環境請改選 **只用內建輕量渲染**，
   或把 KaTeX 下載到 vendor/katex/ 後，把「KaTeX 載入位址」改成 vendor/katex/。
3. 保持「在系統提示詞附加 $…$ 規則」開啟，讓模型穩定輸出可渲染格式。
 
**內建渲染器支援**：希臘字母、箭頭、集合／邏輯／關係符號、上下標、
frac、sqrt、text、mathbb、mathbf、hat、bar、vec、left/right、
sum、int、prod、lim，以及 \R \N \Z \E \Var \argmin \argmax 等巨集。
需要矩陣、對齊環境、化學式等進階排版時請讓 KaTeX 可載入。

## GitHub 同步（選用）

### 為什麼要用
 
- 手機／筆電／桌機看到同一份對話。
- 把舊對話卸載到雲端、本機只留標題，**節省瀏覽器儲存空間**。
- 對話有版本歷史（就是 Git commit），誤刪也能從 repo 找回。

### 設定步驟
 
1. 在 GitHub 建立一個 **Private** repo，例如 my-chat-archive。
2. Settings → Developer settings → **Fine-grained tokens** → Generate new token
   - Repository access：**Only select repositories** → 只選這個 repo
   - Permissions → Repository permissions → **Contents: Read and write**（其他都不要給）
   - 建議設定 90 天到期
3. 本 App → 設定 → **☁️ 同步** → 啟用 → 填入 Token / Owner / Repo → 按「🔌 測試連線」。
4. 按「🔄 立即同步」。之後會在啟動、變更後 5 秒、每 N 分鐘、切換分頁時自動同步。

### repo 結構
 
    my-chat-archive/
    ├─ chats/
    │  ├─ chat_lx3k….json      ← 一個對話一個檔（含刪除墓碑）
    │  ├─ _folders.json        ← 資料夾（含墓碑）
    │  └─ _prompts.json        ← 自訂提示詞（含墓碑）
    └─ backups/
       └─ 2025-01-01T…-before-force-push.json

### 同步邏輯（為什麼可以放心）
 
| 情境 | 行為 |
| --- | --- |
| A 裝置改對話甲、B 裝置改對話乙 | 不同檔案 → **零衝突** |
| A、B 同時改同一個對話 | 後推的人收到 409 → 自動重抓、**三方合併**、再推（重試 3 次） |
| 兩邊各新增了幾則訊息 | 以訊息 id **聯集**，依 seq／時間排序 → **一則都不會少** |
| 同一則訊息兩邊都編輯 | 取 editedAt 較新者 |
| A 刪了訊息 / 資料夾 / 提示詞 | 墓碑傳播 → B 也會刪掉，**不會復活** |
| A 刪了整個對話 | 寫入 tombstone 檔；若 B 之後又編輯了它，會「復活」保住 B 的新內容（較安全） |
| 兩邊 updatedAt 完全相同 | 用 deviceId 字典序決勝負 → 兩台裝置得到完全相同的結果 |
| 內容其實一模一樣 | 指紋相同 → **不下載、不寫回、不推送、不重繪**（不會互相無限推送） |
| 正在生成回覆 | 暫停自動同步，8 秒後再試（畫面不會被打斷） |
| 單一對話 JSON 很大（> 約 900 KB） | 推送自動改走 **Git Data API**（blob → tree → commit → 更新分支），不受 Contents API 約 1 MB 的限制 |
| chats/ 目錄檔案很多（> 1000） | 列目錄改用 **git trees API**，不會像 contents API 一樣被截斷 |
| 沒網路／額度用盡 | 記錄錯誤、60 秒後自動重試；本機照常運作 |
| 對話被標記為暫時對話 | 完全跳過：不建立檔案、不推送、不卸載 |
 
> 未送出的**草稿不會上傳**，也不會被雲端覆蓋。
 
「以本機覆蓋雲端」「以雲端覆蓋本機」藏在 **⚠️ 進階** 裡，需要打字 OVERWRITE 確認，
且執行前會自動建立備份（雲端 backups/ ＋下載一份到你的電腦）。

### 釋放本機空間
 
設定 → ☁️ 同步 → 進階 → **釋放本機空間**：
把最近 N 個以外、**且已確認同步成功**的對話內容從瀏覽器移除，只保留標題（側邊欄顯示 ☁️）。
點開該對話時會自動從 GitHub 下載內容。未同步成功的對話絕不會被卸載；
已卸載的對話在載入前不允許改名／釘選，避免同步時被覆蓋。

### 安全提醒
 
- Token 存在此瀏覽器（可選 localStorage / sessionStorage / 只在記憶體）。**請勿在公用電腦啟用。**
- 一定要用 **private** repo，且 Token 只授權該 repo、只給 Contents 權限。
- **匯出的備份檔永遠不含任何 API Key 與 GitHub Token。**
- 不想用 GitHub？完全不用做任何事——功能預設關閉，且不會發出任何請求。

## 儲存空間（IndexedDB）
 
v2.3 以前所有資料都塞在 localStorage，容量約 5 MB，貼幾張圖就會出現
「瀏覽器儲存空間已滿」。**v2.4 起改用 IndexedDB**。

### 有什麼不同
 
| 項目 | v2.3（localStorage） | v2.4（IndexedDB） |
| --- | --- | --- |
| 容量 | 約 5 MB（硬上限） | 瀏覽器配額，通常為磁碟可用空間的 **~60%**（數 GB 起跳） |
| 寫入方式 | 每次都把**全部對話** `JSON.stringify` 後整包重寫 | **一個對話一筆記錄**，只寫真的有變動的那幾筆 |
| 資料型別 | 只能存字串 | 結構化資料（未來可直接存 Blob） |
| 被瀏覽器清掉的風險 | 有 | 啟動時會呼叫 `navigator.storage.persist()` 申請**持久性儲存** |
| 附件 | 建議關閉「保存附件內容」 | 可安心開啟；`maxFileSizeMB` 也可以放心調大 |

### 自動遷移
 
第一次用新版開啟時會自動把 `orpc:*` 的舊資料搬進 IndexedDB，
成功後刪除 localStorage 中的大宗資料（**API Key 與 GitHub Token 留在原處不動**），
並顯示「已把 N 筆資料搬進 IndexedDB」。整個過程不需要你做任何事，也不會遺失資料。

### 資料庫長什麼樣
 
DevTools → Application → IndexedDB → `orpc-db`：
 
    orpc-db
    ├─ kv        { k: 'orpc:settings',  v: {…} }     設定
    │            { k: 'orpc:folders',   v: [ … ] }   資料夾（含墓碑）
    │            { k: 'orpc:prompts',   v: [ … ] }   自訂提示詞（含墓碑）
    │            { k: 'orpc:modelCache',v: {…} }     OpenRouter 模型清單快取
    │            { k: 'orpc:currentChatId' | 'orpc:github' | 'orpc:syncMeta', … }
    └─ chats     { id: 'chat_lx3k…', title, messages: [ … ], … }   ← 一個對話一筆

### 多分頁一致性
 
同一台裝置同時開多個分頁時：
 
- 任一分頁寫入成功後，會透過 `BroadcastChannel('orpc-sync')` 通知其他分頁重新讀取變動的資料。
- 其他分頁更新快取後，仍交由既有的**內容指紋**判斷要不要重繪——內容沒變就完全不動畫面。
- 不支援 BroadcastChannel 的環境（少數舊瀏覽器）退回各分頁獨立運作，功能不受影響。
 
> v2.4.3 起，其他分頁寫入的內容會自動以「訊息聯集 ＋ updatedAt 較新者勝」合併回本分頁
> （與 GitHub 同步同一套 mergeChat 規則），不再互相覆蓋；只有「同一則訊息被兩邊同時編輯」
> 時才是最後編輯者勝。

### 不支援 IndexedDB 怎麼辦
 
在隱私／無痕模式或極舊的瀏覽器中，若無法開啟 IndexedDB，
會**自動退回 localStorage 後備驅動**（格式與 v2.3 相同），啟動時以 Toast 告知，
功能全部照常，只是又回到約 5 MB 的限制。
 
> ⚠️ 容量變大不代表無限：資料仍然只在**這一台裝置的這一個瀏覽器**裡。
> 換裝置、清瀏覽器資料前，請先「匯出備份」或啟用 GitHub 同步。
 

## 資料與隱私
 
- **完全本機**：對話、設定、提示詞存在瀏覽器的 **IndexedDB（`orpc-db`）**；
  只有金鑰與裝置碼留在 localStorage / sessionStorage。
- **暫時對話比本機更本機**：只存在頁面的記憶體中，不會寫入資料庫、不會出現在備份檔、也不會推送到 GitHub。
- **外部連線**共有三處，全部可控：
  1. 你選擇的供應商 Base URL（OpenRouter 或 Poe）— 必要。
  2. api.github.com — **僅在啟用同步時**。
  3. cdn.jsdelivr.net（KaTeX）— 可改為自架路徑或改用內建渲染器而完全不連。
- **匯出的備份不含任何金鑰**，可安全分享或同步。
- 想完全清除：設定 → 資料 → 清除全部資料（會一併刪除 IndexedDB 與所有金鑰）。

## 常見問題
 
**Q：出現「401 API Key 無效」？**
A：確認選對供應商，且金鑰完整複製、沒有多餘空白。OpenRouter 金鑰為 sk-or-v1- 開頭。
 
**Q：Poe 出現「404 找不到模型」？**
A：Poe 的 bot 名稱**大小寫敏感**，且不時會改版。請到 poe.com 確認實際名稱後，
在「設定 → API → 常用模型清單」修正。
 
**Q：Poe 出現「400 請求被拒」？**
A：本 App 對 Poe 已自動只送出基本參數；若仍發生，請把 Top K / penalty / seed 歸零，
或關閉「串流回應」再試。
 
**Q：出現「402 額度不足」或「429 請求過於頻繁」？**
A：免費模型有速率與每日上限。請稍後再試、換一個模型，或到供應商後台儲值。
 
**Q：模型清單抓不到？**
A：OpenRouter 會自動改用快取或內建備援清單，可在模型選擇器按「↻ 更新清單」重試。
Poe 的清單本來就是手動維護，不會連網抓取。
 
**Q：出現「儲存空間已滿」？**
A：v2.4 起已改用 IndexedDB，容量是瀏覽器配額（通常數 GB），正常使用幾乎不會遇到。
若真的出現，代表**整台裝置的磁碟或瀏覽器配額**吃緊：
1. 啟用 GitHub 同步後使用「釋放本機空間」把舊對話卸載到雲端；
2. 匯出備份後刪除舊對話 / 刪除所有已封存對話；
3. 設定 → 檔案 → 關閉「把附件內容一起保存」。
 
**Q：我的舊對話會不會在升級時不見？**
A：不會。第一次開啟新版會自動把 localStorage 的資料搬進 IndexedDB，
確認寫入成功後才刪除舊副本，並顯示遷移完成的提示。真的不放心，升級前先「匯出全部資料」。
 
**Q：無痕模式下會怎樣？**
A：若瀏覽器不允許開啟 IndexedDB，會自動退回 localStorage 後備模式（約 5 MB），
啟動時會有警告 Toast，其他功能完全正常。
 
**Q：資料變大之後，切換對話會變慢嗎？**
A：對話清單與訊息仍是一次全部載入記憶體，因此**極端大量**（數千個對話）時啟動會變慢。
建議搭配 GitHub 同步的「釋放本機空間」，或封存不用的對話。
 
**Q：啟用 GitHub 同步後畫面會閃爍嗎？**
A：不會。v2.2 起同步只在「本機資料真的被改動」時才重繪，且會比對內容指紋；
生成回覆期間也不會執行自動同步。
 
**Q：數學公式顯示成原始碼？**
A：見「[數學公式](#數學公式)」。最快解法：設定 → 介面 → 渲染引擎改成「只用內建輕量渲染」。
 
**Q：AI 產生的標題出現思考過程或一長串推理？**
A：已內建清洗；若仍發生，請把「標題產生模型」換成非 reasoning 的小模型。

**Q：自動摘要把前面的對話「壓掉」了，我想知道它到底摘了什麼、或不滿意結果？**
A：摘要完全透明可管：頂列的「📝 已摘要 N 則」顯示狀態；🎛️ 本對話設定展開「📝 自動摘要」
即可看到並直接修改摘要文字（按「儲存」生效）；「↺ 只重設進度」可讓同一批舊訊息重新被摘要一次；
「🗑️ 清除摘要」則從頭累積。輸入 `/summary` 也能隨時查看全文與進度。

**Q：GitHub 同步會不會覆蓋掉我另一台電腦的對話？**
A：不會。所有寫入都帶 sha 樂觀鎖，衝突時走三方合併（訊息聯集）。
唯一會覆蓋的是「⚠️ 進階」裡那兩個需要打字確認、且會先備份的操作。
 
**Q：同步顯示 403 權限不足？**
A：Token 需要 **Contents: Read and write**，且 Repository access 要選到那個 repo。
 
**Q：側邊欄的對話變成 ☁️ 打不開？**
A：那是被「釋放本機空間」卸載到雲端的對話。需要啟用同步且有網路，點一下就會自動下載。
 
**Q：語音輸入沒反應？**
A：Web Speech API 主要支援 Chrome / Edge，且需要 HTTPS 或 localhost 並允許麥克風權限。
 
**Q：暫時對話真的不會留下任何痕跡嗎？**
A：不會寫入 IndexedDB、不進備份檔、不同步到 GitHub。但**提問內容仍然會送到你選擇的供應商**
（OpenRouter / Poe），那部分請依供應商的隱私政策判斷。
 
**Q：我在暫時對話裡問出了好東西，想留下來？**
A：側邊欄該對話按 **💾**（或輸入 `/keep`）轉為永久對話，內容與訊息 id 都會保留；
或直接用 📤 匯出成 Markdown / HTML。
 
**Q：生成回覆時切到別的對話，答案會不見嗎？**
A：不會。v2.3 起生成工作綁在對話上，背景會繼續完成，側邊欄會顯示 ⏳；切回去就能看到完整內容。
 
**Q：怎麼調整資料夾順序？**
A：滑過資料夾標頭會出現 ↑ ↓ 按鈕；也可以直接拖曳資料夾標頭放到目標資料夾上（插到它前面）。
順序存在資料夾資料裡，會跟著 GitHub 同步到其他裝置。
 
**Q：側邊欄太窄／太寬？**
A：拖曳側邊欄的右緣即可（200–520 px），**雙擊**右緣還原預設。寬度會自動記住；
也可以用 Tab 聚焦右緣把手後，按 ← → 每次 16px 微調、Home 還原預設。
手機版是抽屜式側邊欄，不提供調整。
 
**Q：某則回覆很長，怎麼快速回到它的開頭？**
A：滑鼠移到該則訊息上，右上角會出現 **⬆ 頂部** 懸浮按鈕，點一下即平滑捲回該則的第一行。
 
**Q：附件加太多，輸入區被擠得很長？**
A：附件列在數量較多時會自動收成一行摘要（📎 N 個附件 · 總大小）；點摘要列或「+N」可展開，再點一次收合。
展開時超出高度可捲動，不會推擠聊天內容。附件數量沒有上限。
 
**Q：回覆失敗（紅色的 ⛔ 錯誤）要怎麼重試？**
A：滑到該則訊息上，操作列會出現 **↻ 重試**——沿用原本的模型與上下文重送，成功後原地替換這則回覆，訊息位置與 id 都不變。
 
**Q：回覆被截斷了（寫到一半就停）？**
A：若截斷原因是輸出長度上限，該則訊息尾端會出現 **⏩ 繼續生成** 按鈕，點擊即從中斷處接著寫、append 回同一則；可以連續按多次直到寫完。
 
**Q：AI 的回覆有幻覺或廢話，想直接改掉？**
A：助理訊息的操作列也有 **✏️ 編輯**——修改後按「僅儲存」即可，不會觸發重新生成。（使用者訊息的編輯仍提供「儲存並重新送出」。）
 
**Q：長對話裡想快速跳回某幾則重要訊息？**
A：在該則訊息的操作列按 **🔖 書籤**。加入後對話頂部會出現書籤列，點 chip 直接跳轉；
也可以用 <kbd>Alt</kbd>+<kbd>[</kbd> / <kbd>]</kbd> 在書籤間循環切換。書籤會跟著 GitHub 同步到其他裝置。
 
**Q：程式碼裡有 ``` 或引號，code block 會被斷開？**
A：v2.4.2 起圍欄改用 **CommonMark 逐行解析**：關欄必須「獨占一行、與開欄同字元且長度足夠」，
因此 `const md = "```";` 這類內容不會再誤斷區塊。若程式碼本身含「行首恰好是 ``` 的獨立行」
（例如在教 Markdown 語法），請讓模型改用四個反引號的外層圍欄或 `~~~` 圍欄。
 
**Q：想要更專注的寫作／閱讀畫面？**
A：按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> 進入**專注模式**：側邊欄與頂列隱藏，只留訊息與輸入區。
再按一次或 <kbd>Esc</kbd> 退出。
